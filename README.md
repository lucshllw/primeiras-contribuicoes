# Primeiras contribuições no GitHub

Um guia em português para começar a colaborar com projetos de forma útil, segura e respeitosa com quem mantém o código.

Você não precisa começar criando uma funcionalidade grande. Uma reprodução clara de um bug, um exemplo que realmente funciona ou uma instrução de instalação corrigida podem ajudar bastante.

## Por onde começar

1. Escolha uma ferramenta que você já usa ou quer entender.
2. Leia o README, o `CONTRIBUTING.md`, as regras da comunidade e eventuais políticas de uso de IA.
3. Confira se o problema já tem issue, responsável ou pull request em andamento.
4. Reproduza o problema e defina uma mudança pequena.
5. Faça a alteração em uma branch, execute as verificações do projeto e abra uma PR explicando o resultado.
6. Acompanhe os comentários. Uma PR aberta ainda é uma proposta; a aceitação depende dos mantenedores.

## Pequeno glossário

| Termo | O que significa aqui |
| --- | --- |
| Repositório | Projeto com arquivos e histórico de alterações. |
| Fork | Sua cópia de um repositório no GitHub. |
| Branch | Linha de trabalho separada para uma mudança. |
| Commit | Registro de uma alteração no histórico local. |
| Push | Envio dos commits para um repositório remoto. |
| Issue | Relato ou discussão sobre um problema ou proposta. |
| Pull request (PR) | Pedido para revisar e incorporar alterações de uma branch. |
| Merge | Integração de alterações ao histórico de destino. |

## Dicas que evitam retrabalho

- Procure `good first issue` e `help wanted`, mas leia o contexto: uma etiqueta não garante que a tarefa esteja disponível ou seja simples.
- Não abra várias PRs repetindo a mesma correção ou alterando apenas formatação sem necessidade.
- Não copie uma sugestão sem entender o que ela muda. Se usar IA, confira as regras do projeto, revise a saída, teste e informe a assistência quando apropriado.
- Para bugs, escreva o que acontecia antes, o que mudou e como conferir a correção.
- Respeite as decisões dos mantenedores e ajuste a mesma PR quando receber pedidos de revisão.
- Não crie contribuições artificiais para preencher o gráfico do perfil. Trabalhe em melhorias que alguém consegue avaliar e utilizar.
